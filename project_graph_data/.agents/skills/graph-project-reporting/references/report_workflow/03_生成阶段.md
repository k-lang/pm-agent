# 阶段三：生成阶段

## 🎯 目标

基于结构化框架，生成准确且生动的回答。

**核心原则**：
- ✅ 按框架填充，而非边想边写
- ✅ 数据准确：所有数字来自原始数据
- ✅ 表达生动：使用过渡语和因果关系
- ✅ 状态准确：包括未完成、受阻等真实情况
- ✅ 写作时同步落出处，不要写完再临时补来源

---

## 🔧 Step 3.1：按框架逐章节生成

**写作流程**：
1. 按照阶段二确定的框架结构
2. 逐章节填充内容
3. 每章节包含：背景→过程→数据→发现→影响
4. 先写论据并插入对应出处标记，再基于这些论据给出解读

**保持原逻辑的要求**：
- 不要因为加出处而改写原本已经成立的汇报逻辑
- 如果原文原本就已经自然地从事实走向判断，只需要把出处补在这些事实和现象上
- 只要解读确实由前文论据支撑，就不必机械地把每个结论句都改写成“论据清单 + 结论”格式
- 重点是让证据链可见，而不是让文风变硬、变碎或变成法条式证明

**引用落点规则**：
- 关键数据、关键案例、关键事实、时间节点、原始现象描述必须就近标注
- `final_report.md` 默认使用脚注，例如 `[^E12]`
- 脚注内容至少包含：来源层级、相对路径、定位信息；必要时补 1 句原文摘录
- 对话中的即时回答可用行内短标记，例如 `[来源：notes/xxx.md]`
- 不要整章末尾统一堆一串来源，避免读者无法判断每条证据支撑了什么
- 对解读性句子，优先采用“论据句带出处 + 解读句紧随其后”的写法
- 如果原段落里论据和解读本来就自然交织，允许保留原节奏，只要出处仍明确挂在对应论据上

**推荐写法**：
- 好写法：`5月18日的工作笔记明确记录，团队因线上稳定性不足暂停A方案，转向B方案验证。[^E12] 同期节点历史也出现了目标切换痕迹。[^E13] 这说明当时的方案调整并非单点试错，而是稳定性问题推动的阶段性转向。`
- 避免写法：`当时发生了阶段性转向。[^E12]`（如果 `E12` 实际只直接支撑原始现象，而不直接支撑整句解读）
- 避免写法：为了加脚注，把原本流畅的一段强行拆成多条生硬的“证据清单”，导致汇报失去节奏

**表述强度规则**：
- `notes` 支撑的判断可以正常下结论
- 只有 `nodes` 支撑时，要避免写得像直接来自原始笔记
- 只有 `changelog` 支撑时，要明确使用更保守的表达，如“从变更记录看”“按当前记录推断”

## 🔧 Step 3.2：生动表达技巧

**技巧1：突出转折点**
- ❌ 平铺直叙："我们做了A，然后做了B"
- ✅ 突出转折："A方案遇到了X问题，这促使我们..."

**技巧2：讲清楚因果关系**
- ❌ 只说结果："指标从A%提升到B%"
- ✅ 说清原因："通过XX策略，解决了YY问题，指标从A%提升到B%"

**技巧3：使用过渡语连接**
- ❌ 生硬罗列："第一，...第二，...第三，..."
- ✅ 自然过渡："在解决了X问题后，我们发现..."、"这一发现促使我们..."

**技巧4：用真实案例说明抽象概念**
- ❌ 抽象描述："存在理解偏差问题"
- ✅ 案例说明："例如，[具体场景]，这说明了..."
- **注意**：案例必须来自原始笔记，不可编造

**技巧5：数据对比要有参照**
- ❌ 孤立数据："命中率达到70%"
- ✅ 对比呈现："命中率从之前的40%提升到70%，提升了30个百分点"

## 🔧 Step 3.3：准确性红线

**绝对不能做的事**：

| 禁止行为 | 说明 |
|---------|------|
| 编造数据 | 所有数字必须来自原始记录 |
| 虚构案例 | 案例必须来自笔记，不可创造 |
| 自行计算 | 不做原始数据中没有的计算 |
| 美化状态 | 如实描述未完成、受阻等情况 |
| 简化因果 | 不省略重要的中间环节 |

**必须做到的事**：

| 必做行为 | 说明 |
|---------|------|
| 数据溯源 | 每个数字都能在原始记录中找到 |
| 状态准确 | 区分"已完成"、"进行中"、"受阻" |
| 异常解释 | 进度下降、状态回退必须说明原因 |
| 保留细节 | 重要的区分细节不能省略 |
| 就近引用 | 关键论据旁边能直接看到出处 |

## 🔧 Step 3.4：不同问题类型的输出规范

### 宏观概述类

**结构建议**：
1. 项目背景/起因
2. 关键进展（按工作线或时间线组织）
3. 遇到的问题
4. 解决思路
5. 当前状态
6. 下一步计划

**篇幅**：完整汇报，可较长

### 专题演进类

**结构建议**：
1. 专题背景
2. 演变过程（按阶段）
3. 关键转折点
4. 当前状态

**篇幅**：中等长度，聚焦该专题

### 细节查询类

**结构建议**：
1. 直接回答问题
2. 补充上下文（如有必要）
3. 相关数据来源

**篇幅**：简短精确

### 对比分析类

**结构建议**：
1. 对比维度说明
2. 对比表格或并列描述
3. 差异原因分析

**篇幅**：中等长度

### 原因追溯类

**结构建议**：
1. 结果/现象描述
2. 因果链条展开
3. 根本原因总结

**篇幅**：根据因果链复杂度调整
