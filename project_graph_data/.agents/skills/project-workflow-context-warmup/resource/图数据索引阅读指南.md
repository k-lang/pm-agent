# 图数据索引阅读指南

本指南供 `project-workflow-context-warmup` 使用。目标是帮助模型在 warmup session 中快速建立项目主干上下文，而不是生成正式汇报。

## 核心原则

不要批量读取所有节点、所有边或所有 notes。项目图数据变大后，批量读取会造成信息过载，也会把上下文窗口消耗在无关细节上。

正确方法是“索引驱动、按需深入”：

1. 先读项目级索引和现成总结，建立主干。
2. 再读 summary/history，定位关键节点和关联节点。
3. 只有当某个判断需要原始依据时，才下钻到 notes 或 source。
4. 输出时说明“后续要查什么应该去哪条线继续查”，不要假装预热已经完成所有细节定位。

## 数据层级与权威性

项目图数据通常可以按以下层级理解：

```text
notes/ 与 source/    原始工作记录和用户资料，最权威
nodes/               结构化图数据，承载节点状态、摘要、历史和关系
descriptions_output/ 快速索引，用于导航和概览
changes/changelog    时间线索引和 step 入口
```

权威性优先级：

```text
notes/source > nodes/descriptions_output > changelog
```

`changelog` 适合提供时间锚点、阶段切换和关键 step，但不应单独支撑重要结论。若只能从 `changelog` 得到某个判断，应明确标记为弱证据。

## 预热读取顺序

### 1. 项目入口

优先查看：

- `README.md`
- `report_output/current_final_report.md`
- 最近的 `report_output/*/final_report.md`

用途：

- 识别项目背景、业务场景、初始目标。
- 快速获得已有总结中的主线判断。
- 判断当前项目是否已经有明确阶段划分。

注意：

- 这些材料可帮助建立主干，但不要照搬成正式报告。
- 如果报告和图数据、notes 有冲突，优先以后者为准。

### 2. 时间线入口

查看：

- `changes/changelog.txt`

用途：

- 识别关键 step。
- 识别最近变化。
- 发现工作线分叉、目标调整、问题状态变化、结果产生等节点。

预热阶段不要求完整复盘所有 step，但要抓住：

- 初始目标或需求出现的位置。
- 关键问题出现的位置。
- 重要工作块和工作项启动的位置。
- 关键结果产生的位置。
- 最近一次或几次对项目状态有影响的变化。

### 3. 快速节点索引

查看：

- `descriptions_output/description_summary/`
- `descriptions_output/history/`

用途：

- `description_summary` 用于了解节点当前状态和一句话概括。
- `history` 用于了解节点演变、关联节点和 step 线索。

读取策略：

- 不要全量 cat 某类节点。
- 先从 README、report、changelog 中识别节点 ID。
- 对这些节点读取 summary/history。
- 从 history 中提取关联节点，再按需读取关联节点的 summary/history。

### 4. 原始节点

查看：

- `nodes/<type>/<id>.json`

用途：

- 当前三个索引层不足以判断时，读取原始节点。
- 核对状态、score、结构字段或完整 serialized data。

预热阶段一般不需要大量读取 `nodes`。只有在 summary/history 不足以判断某条主线时才读。

### 5. 原始工作笔记和资源

查看：

- `notes/`
- `source/`

用途：

- 支撑关键判断。
- 查清某个方案为什么调整、某个问题为什么产生、某个结果怎么得到。
- 获取用户上传的架构、需求、会议纪要或外部资料。

定位 notes 的常用路径：

```text
changelog 或 report 中发现关键节点
-> 读取该节点 summary/history
-> 从 history 找到相关 work_item
-> 读取 work_item summary
-> 根据 summary 末尾的工作笔记路径读取 notes
```

如果 work_item summary 没有工作笔记路径，说明预热阶段可先用 summary/history 建立弱理解，并在输出里标记为待确认。

## warmup 输出应包含的导航信息

预热输出不只是“当前项目是什么”，还要告诉后续 workflow chat：

- 关键目标：哪些 goal 是当前主线。
- 关键工作线：哪些 work_block/work_item 是后续推进最可能引用的上下文。
- 关键问题：哪些 issue 仍可能影响后续计划或图操作。
- 关键结果：哪些 result 改变了目标状态、问题状态或工作策略。
- 最近变化：最近发生了什么，可能导致下一步计划调整。
- 查找地图：如果用户问某类事情，应先看哪些节点、history 或 notes。
- 上下文缺口：预热时没能确认但后续推进可能需要确认的内容。

## 不要做的事

- 不要生成正式项目汇报。
- 不要写 `report_output/`。
- 不要生成工作笔记或图操作草案。
- 不要调用 `workflow_action`。
- 不要把本指南或目录结构本身当作最终上下文。
- 不要声称已经理解所有细节；预热只是建立主干地图。
