# 阶段二：结构化梳理阶段

## 🎯 目标

基于收集的数据，建立多维度结构化框架，为生成回答做准备。

**核心原则**：
- ✅ 这是决定回答质量的核心阶段
- ✅ 不同问题类型有不同的梳理维度
- ✅ 必须识别认知演变和转折点
- ✅ 必须梳理因果链条
- ✅ 每个核心判断都要提前绑定证据，不要到写作阶段才补引用

---

## 🔧 通用梳理维度

无论问题类型，都需要回答以下核心问题：

| 维度 | 核心问题 |
|-----|---------|
| 是什么 | 事实、数据、状态 |
| 为什么 | 原因、背景、触发因素 |
| 怎么变的 | 演变过程、转折点 |
| 和什么相关 | 关联的工作线、问题、目标 |

---

## 🔧 宏观概述类问题的梳理

### Step 2.1：识别并行工作线

从时间线矩阵中提取：
- 有哪几条并行推进的工作线？
- 每条线的起止时间？
- 每条线的关键里程碑？
- 线与线之间的依赖和交互？

**输出格式**：
```
工作线A：[名称] (起止时间)
  - 里程碑1：[时间] [事件] [数据]
  - 里程碑2：...
  - 当前状态：...

工作线B：[名称] (起止时间)
  - ...
```

### Step 2.2：追溯认知演变

识别"同一事物在不同阶段的认知变化"：

**需要追溯的内容**：
- 哪些问题的理解发生了变化？
- 哪些目标的定义被调整了？
- 哪些指标的解读被修正了？

**输出格式**：
```
[问题/目标/指标]的认知演变：
  - 初期（时间）：[认知内容] [数据]
  - 转折（时间）：[发现了什么] [为什么改变]
  - 当前（时间）：[认知内容] [数据]
```

### Step 2.3：标记关键转折点

识别"改变项目走向的关键时刻"：

**转折点类型**：
- 外部事件（客户要求、时间压力、政策变化）
- 内部发现（分析结果、验证失败、方案缺陷）
- 方法突破（新思路、新方案、关键洞察）

**输出格式**：
```
转折点：[时间] [事件名称]
  - 背景：[之前是什么状态]
  - 触发：[什么导致了转折]
  - 影响：[之后发生了什么变化]
  - 数据：[相关数字]
```

### Step 2.4：构建因果链条

梳理"为什么会这样"的逻辑：

**因果链条要素**：
- 问题A → 导致 → 目标B
- 目标B → 触发 → 工作C
- 工作C → 产生 → 结果D
- 结果D → 影响 → 问题A的认知

**注意**：
- 识别多层因果关系（不只是直接因果）
- 区分直接原因和根本原因

### Step 2.5：建立汇报框架

基于上述梳理，确定回答结构：

**输出格式**：
```
一、[章节名]
  - 主要内容：...
  - 涉及工作线：...
  - 关键数据：...
  - 转折点：...

二、[章节名]
  - ...
```

### Step 2.6：把证据绑定到章节判断

**硬要求**：
- 每个章节先列“本章核心判断”，并拆出支撑这个判断的原始论据，再给论据挂上证据 ID
- 默认优先使用 `notes` 证据；`nodes` 作为补充；`changelog` 仅作时间锚点或弱证据
- 如果同一判断有多条证据，优先展示最高等级来源，必要时保留次级来源辅助说明
- 这一步的目的不是改变章节的原有逻辑，而是把原本隐含在写作过程中的论据链显式整理出来，方便生成时补出处

**推荐格式**：
```md
## 第二阶段：方案切换与验证收缩
- 核心判断1：5月中旬发生方案切换
  - 论据A：5月18日笔记明确记录暂停A方案、转向B方案（E12）
  - 论据B：同阶段节点历史中出现目标和工作线切换（E13）
- 核心判断2：切换主因是线上稳定性与口径问题
  - 论据A：原始笔记记录了线上稳定性不足（E12）
  - 论据B：结构化节点补充了口径问题的影响范围（E15)
- 核心判断3：当前仅有 changelog 支撑，属于弱证据，生成时需降低表述确定性
  - 论据A：变更记录中出现阶段切换，但没有找到原始笔记补强（E21）
```

**冲突处理**：
- 如果 `notes`、`nodes`、`changelog` 之间存在冲突，优先相信 `notes`
- 若冲突无法消解，要在大纲中显式记录“证据分歧”，不要在生成阶段偷偷抹平
- 若章节中的某个重要判断还没有 `notes` 支撑，要在大纲里标注“待补强”
- 如果原有框架已经成熟，不要为了“论据绑定”重写章节结构；只需给既有判断补上清晰的论据映射

## 🔧 其他问题类型的梳理

### 专题演进类问题

**梳理重点**：
- 该专题的完整演变脉络
- 每个阶段的状态和数据
- 关键转折和原因
- 与其他工作线的关联

### 细节查询类问题

**梳理重点**：
- 该数据的来源和上下文
- 相关的前因后果
- 可能的关联信息

### 对比分析类问题

**梳理重点**：
- 对比维度的确定
- 每个维度的数据提取
- 差异点和原因分析

### 原因追溯类问题

**梳理重点**：
- 因果链条的完整追溯
- 每个环节的触发因素
- 决策背景和依据

---

## 📤 输出物

**结构化框架**（内存中或写入中间文件）：
1. 并行工作线清单
2. 认知演变清单
3. 转折点清单
4. 因果链条
5. 回答框架大纲
6. 章节判断与证据 ID 的绑定关系

---

## ✅ 质量检查清单

### 宏观概述类问题必检项
- [ ] 是否识别了所有并行工作线？
- [ ] 是否追溯了关键认知的演变？
- [ ] 是否标记了所有重大转折点？
- [ ] 进度变化是否都有解释（特别是下降）？
- [ ] 因果链条是否完整？
- [ ] 每个重要判断是否都已绑定证据 ID？

### 通用检查项
- [ ] 结构化框架是否清晰？
- [ ] 关键数据是否已标注？
- [ ] 是否已区分强证据（notes）与弱证据（仅 changelog 等）？
- [ ] 是否已记录待补强和证据分歧点？
- [ ] 是否准备好进入生成阶段？
